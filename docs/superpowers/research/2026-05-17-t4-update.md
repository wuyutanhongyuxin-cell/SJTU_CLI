## 0. 网络环境与路径选择

| 域 | 公网状态 | 结论 |
|---|---|---|
| `ecard.sjtu.edu.cn` | `302 → restrict.sjtu.edu.cn` | 公网不可达（与 S3e CP-E0.1 4 月观察一致） |
| `card.sjtu.edu.cn` | `302 → weixin.sjtu.edu.cn/xxzx/sjtu-net/ecard/ecard.php` | 微信 H5 入口，**非独立 REST API** |
| `api.sjtu.edu.cn/v1/me/card/user?access_token=INVALID` | `HTTP 200 + {"errno":10002,"error":"Authentication Failed","total":0}` | **公网可达**，envelope `{errno,error,total}` 与 elec/services 同款 |
| `developer.sjtu.edu.cn/api/card.html` | 200 | 完整契约可读 |

**结论**：T4 必须走**路径 C（OAuth2 Authorization Code + api.sjtu.edu.cn）**。
路径 A（ecard CAS）永久绑定校园网，未来用户出差/在校外即不可用，不再作为主路径。

## 1. 预研报告偏差修正

### 修正 1：余额端点路径

| 项 | 预研报告写 | 实际官方文档 |
|---|---|---|
| 端点 | `GET /v1/me/card/user` | **`GET /v1/me/card`** |
| scope | `card_info` 或 `manage_card` | `card_info`（**仅此一个**，不复合 manage_card） |
| 说明 | "卡用户信息" | "获取用户校园卡信息" |

注：`/v1/me/card/user` 是"按学工号查身份"端点（scope `manage_card` 或 `card_info`，需 `userCode` 参数），与"查我自己的卡"无关。

### 修正 2：金额类型

| 项 | 预研报告写 | 实际官方文档 |
|---|---|---|
| `cardBalance` | "可能 string 也可能 number" | **`double`** |
| `transBalance` | "可能 string 也可能 number" | **`double`** |
| transactions `amount` / `cardBalance` | 未提 | **`double`**（消费为负数） |

**Decimal 处理路线**（仍按 CLAUDE.md 硬约束）：
- 与 elec 同款复用 `models::decimal_str_or_num` 自定义 ser/de 把 `double` → `Decimal` 收口
- 反序列化时 `Visitor::visit_f64` 走 `Decimal::from_f64_retain(v).ok_or(...)` 转换；NaN/Infinity 抛错
- 序列化全走 `serialize_str` 避开 JSON `f64` 精度坑
- 累加（如 history 求和）一律 `Decimal` 链式 `+`，绝不途中转 f64

### 修正 3：envelope

| 项 | 预研报告写 | 实际官方文档 |
|---|---|---|
| envelope | "需现场观察" | **`{errno, error, total, entities}`** 与 elec/services 完全同款 |
| 错误响应 | "未知" | `HTTP 200 + errno != 0`（不是 4xx）；如 `errno=10002 / error="Authentication Failed"` |

**复用决策**：不为 card 子系统新造 envelope 类型；复用 elec 同形 generic `Envelope<T>` + `#[serde(bound(deserialize = "T: Deserialize<'de>"))]` 防 `T: Default` 传染（elec 已踩过此坑）。

## 2. transactions 端点完整参数表

`GET https://api.sjtu.edu.cn/v1/me/card/transactions`，scope = `card_transactions`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `access_token` | string | ✓ | OAuth2 Bearer，URL query 形式也可 |
| `cardNo` | string | ✗ | 可省略，省略时服务端随机选一张；本 CLI **首跑 GET /v1/me/card 拿主卡 cardNo 后必传**，避免多卡用户的不确定性 |
| `beginDate` | long ms_ts | ✗ (但若 `limit=0` 则必传) | Unix 1970 起毫秒数；不传时默认 1970-01-01 |
| `endDate` | long ms_ts | ✗ | 不传时默认今日 |
| `orderBy` | string | ✗ | `dateTime`（默认，按消费时间） / `dateTimeAccount`（按入账时间） |
| `start` | int | ✗ | 0 起；指定 >0 时必传 `limit` 且为 `limit` 整数倍 |
| `limit` | int | ✗ | **服务端硬限 0-100**；0 = 不分页（必传 `beginDate`） |

### transactions 单条 entity 字段

```text
{
  "dateTime"      : long,    // Unix ms — 消费时间
  "dateTimAccount": long,    // ⚠️ 注意拼写：少个 e；仅 orderBy=dateTimeAccount 时返回
  "system"        : string,  // 系统名（如 "新闵行第二食堂"）
  "merchantNo"    : string,  // 商户号
  "merchant"      : string,  // 商户名（如 "大众餐厅"）
  "description"   : string,  // 交易名称（如 "持卡人消费"）
  "amount"        : double,  // 消费为负、充值为正
  "cardBalance"   : double,  // 交易后卡余额
}
```

**`dateTimAccount` 拼写陷阱**：必须 `#[serde(rename = "dateTimAccount")]`，否则反序列化会漏。已在 spec 草案 §4.4 字段表落定。

## 3. OAuth2 Authorization Code 流程（关键决策已定）

### 3.1 端点

```text
Authorization URL : https://jaccount.sjtu.edu.cn/oauth2/authorize
Access Token URL  : https://jaccount.sjtu.edu.cn/oauth2/token
Logout URL        : https://jaccount.sjtu.edu.cn/oauth2/logout
```

### 3.2 Token 形态

```json
{
  "expires_in": 1800,
  "token_type": "Bearer",
  "refresh_token": "...",
  "access_token": "..."
}
```

- access_token 有效期 **1800 秒**（30 分钟）
- 用 `refresh_token` + `grant_type=refresh_token` 续期，**用户无需重新授权**
- token 落 `~/.sjtu-cli/sub_sessions/card_oauth.json` + chmod 600

### 3.3 scope 选择

| scope code | 位值 | 用途 | A 模式支持 |
|---|---|---|---|
| `card_info` | `1<<39` | 余额、卡号、状态 | ✓ |
| `card_transactions` | `1<<40` | 消费记录 | ✓（**仅 A 模式**） |

合并：URL query `scope=card_info+card_transactions`（空格分隔），或 `scope=1649267441664`（位 OR 后十进制）。spec 选**空格分隔**形式，可读性高且文档主推。

**不申请**：`write_card_info` / `manage_card` —— 写入 scope CLI 红线不接，避免审批时被审核"为什么 read-only CLI 要写入权限"。

### 3.4 PKCE / state

- **state**: 必传（CSRF 防御）。CLI 启动时 `rand::rng().random::<u64>()` 生成 32 字符 base64。
- **PKCE**: 文档未提，但 RFC6749 推荐。先**不实现**（公开客户端 PKCE 是后续扩展，等申请获批确认服务端是否要求 `code_challenge`），spec 留一个 open question。

### 3.5 redirect_uri

- CLI 启动时本地 listen `127.0.0.1:<random_port>` 接 callback
- 默认端口范围 `45100-45200`（避开常见占用），失败时随机
- 申请时 redirect_uri 填 `http://127.0.0.1:<固定端口>/callback` —— **需要审批确认服务端是否接受 localhost + 通配端口**

**Open Question OQ-1**：开发者平台是否支持 `http://127.0.0.1:*/callback` 通配，还是必须精确匹配某固定端口？审批申请页面是必填字段，若必填精确 → spec 选固定端口 `45123`。

## 4. 用户操作清单（你需要做的）

### 步骤 1：登录开发者平台

访问 `https://developer.sjtu.edu.cn/` → jAccount 登录 → 找"我的应用" / "应用注册"入口。

### 步骤 2：申请新应用

填写表单（预估字段，以实际页面为准）：

| 字段 | 填什么 |
|---|---|
| 应用名称 | `sjtu-cli 一卡通查询`（中文，便于审核理解） |
| 应用类型 | "桌面应用" / "命令行工具" / 类似（看下拉选项） |
| 应用描述 | "上海交通大学 CLI 工具，仅做一卡通余额查询和消费记录只读展示，不涉及任何写操作或资金变动" |
| redirect_uri | `http://127.0.0.1:45123/callback`（**spec 选定端口**；如表单允许多个 URI，再加 `http://localhost:45123/callback` 作 host 兼容） |
| scope | 勾选 `card_info` + `card_transactions`（**仅这两个**） |
| 授权模式 | "Authorization Code"（A 模式） |
| 上线状态 | 测试 / 试运行（避免审核走生产流程） |
| 联系邮箱 | 你的 jAccount 邮箱 |

**注意红线**：
- 描述里**明确写"只读"** —— 否则审核可能要求附加合规材料
- **不要勾** `manage_card` / `write_card_info` / `privacy` / `essential`（后者会拿走身份信息，超出 CLI 需要）
- redirect_uri 一定要 http（不是 https，因为 CLI 本地 server 不挂证书）

### 步骤 3：等审批 + 把申请单号告诉我

审批 3 工作日。批准后你会拿到：
- `client_id`（公开，可入仓库或配置文件）
- `client_secret`（**敏感**，必须落 `~/.sjtu-cli/card_oauth_secret.txt` chmod 600，绝不入仓库）

### 步骤 4（审批中可同步做）

我同期完成 spec → plan → TDD 代码骨架（mockito 单测先行，token 拿到后 1-2 小时上 4 个真机 checkpoint）。

## 6. 与 CAS retry 层（T8）的耦合

T8 已经完成（2026-05-16）。但 T4 走 OAuth2，**不复用 CAS retry helper**：

- CAS retry 是为 jwc/elec/services 的 cookie session 设计的（stale 时 cas_login refresh）
- OAuth2 access_token 有独立的 refresh_token 续期机制，**不走 CAS**

需新建：`src/auth/oauth2_dev/refresh.rs::with_token_refresh<F,Fut,T>(...)` —— 同构 canvas_video 的 `with_token_refresh`，第一次 401/`errno=10002` 时用 refresh_token 续 access_token 后重试一次。
