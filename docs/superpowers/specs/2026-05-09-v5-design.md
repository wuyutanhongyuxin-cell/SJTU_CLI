## V5.A — LTI Bootstrap 缓存

### 问题

`Client::connect()` 内部每次都跑完整 LTI launch（`cas_login → headless Chrome → exchange_token`），墙钟 21-30s。`cas_login` 自身已有 sub_session 缓存（命中 7ms），瓶颈在 Chrome 阶段（~20s 抓 tokenId + v.sjtu cookie）。token 自带 1-3h TTL，cour_id / lti_course_id 长期稳定。

跨命令重抓的浪费场景：
- `sjtu canvas-video list 88168` → `download 88168 --lecture 1` → `download 88168 --lecture 2` 三条命令各付 21-30s
- 用户调研态频繁 list / download 切换更明显

### 决策

**30min 固定 TTL + 业务失败回退**（用户在 brainstorming Q1 选定）：保守 30min（远低于 token 1-3h TTL），命令调用首次业务失败（401 / `code != 0`）时清缓存重跑 LTI launch 一次。

**未取**：1h TTL + 廉价探针（每次多 200ms 网络往返），不设 TTL + 失败重建（首次失败错误模式未实测）。

### 模块布局

### CachedBootstrap 序列化结构

```rust
// src/apps/canvas_video/cache.rs
use chrono::{DateTime, Utc};
use serde::{Deserialize, Serialize};

const TTL_SECS: u64 = 1800;  // 30min

#[derive(Serialize, Deserialize)]
struct CachedBootstrap {
    course_id: u64,                // 防错配
    lti_tool_id: u64,              // 防错配
    saved_at: DateTime<Utc>,       // TTL 起点
    ttl_secs: u64,                 // 写到文件以便升级 TTL 时旧文件仍可读
    token: String,                 // HS512 jwt（含 PII，文件 600 权限保护）
    cour_id: String,               // RSA encrypted（与 course_id 1:1）
    lti_course_id: String,         // 32-hex
    session_cookies: Vec<crate::cookies::Cookie>,
}
```

文件路径：`~/.sjtu-cli/sub_sessions/canvas_video_bootstrap_<course_id>_<lti_tool_id>.json`，权限 600（`cookies::sub_session_path` 已支持路径防注入：禁 `.` / `/` / `\` / 空格 / 控制字符）。

### 业务失败回退（30min 内 token 提前作废的边界）

token 在 30min 窗口内被服务端提前作废的场景（罕见但要兜）：handlers 层加共享 helper：

```rust
// src/commands/canvas_video/handlers.rs（新增）
pub(super) async fn with_token_refresh<F, Fut, T>(
    course_id: u64,
    lti_tool_id: u64,
    op: F,
) -> Result<T>
where
    F: Fn(Arc<Client>) -> Fut,
    Fut: Future<Output = Result<T>>,
{
    let client = Arc::new(Client::connect(course_id, lti_tool_id).await?);
    match op(client.clone()).await {
        Ok(v) => Ok(v),
        Err(e) if looks_like_token_invalid(&e) => {
            cache::clear(Some(course_id), Some(lti_tool_id))?;
            let client2 = Arc::new(Client::connect(course_id, lti_tool_id).await?);
            op(client2).await
        }
        Err(e) => Err(e),
    }
}

fn looks_like_token_invalid(e: &anyhow::Error) -> bool {
    let s = e.to_string();
    // 业务侧失败：v.sjtu envelope code != "0" 或 success == false
    s.contains("业务失败 code") ||
    // HTTP 401 / 403 / "未授权" 字样
    s.contains("401") || s.contains("403") || s.contains("未授权")
}
```

**适用范围**：
- `cmd_list`：包整个 list_lectures 调用。失败重试 1 次。
- `cmd_download`（单讲单 channel）：包整个 download_one_channel 调用。失败重试 1 次。
- `cmd_download_batch`（批量）**不**整体包：批量内部的多讲循环若中途某讲 token 失败，由 V4 既有 fail-soft 把那讲计入 errors，整批继续；用户复跑命令时，V4 skip-via-fs 让已完成讲跳过，新的 `Client::connect` 走 V5.A 失效路径自动重建缓存。**理由**：批量整体 retry 等于把 50-70min 的批量再跑一遍，得不偿失；fail-soft + 复跑幂等已是更好的恢复路径。

**成本**：`with_token_refresh` 调 `Client::connect` 两次时，第二次 cas_login 仍命中（cas 自身缓存独立），所以失败回退总成本 = 一次 LTI launch (~20s) 而非两次。

### 新 CLI 命令

```
sjtu canvas-video clear-cache [--course <id>] [--all]
```

行为：
- `--course <id>`（不带 `--tool`）：删 `canvas_video_bootstrap_<id>_*.json`（多 tool_id 全清）
- `--all` 或 默认：删所有 `canvas_video_bootstrap_*.json`
- 二选一互斥（clap `conflicts_with`）

输出 envelope：
```yaml

```

### 单测（3 个，加在 `tests_parse.rs` 而非新建文件防超 200 行）

1. `cache_round_trip`：构造 Bootstrap → save → load → 反序列化对比所有字段
2. `cache_expired_returns_none`：手填 saved_at = now - 31min → load 返回 None

### 风险与缓解

- **风险**：cache.rs 内部依赖 `chrono::Utc`，若 deserialize 旧 RFC3339 字符串失败 → load 返回 None 自动重建，不会 panic
- **风险**：30min 内 token 被服务端提前作废 → with_token_refresh 兜底 1 次
- **风险**：用户切换学期后 lti_tool_id 变化 → 文件名包含 lti_tool_id 自然隔离
- **风险**：用户多 SJTU 账号切换 → 切账号后 `sjtu logout` 已清主 session，但 sub_session 文件不清。**缓解**：在 `auth_cmds::cmd_logout` 里追加 `cache::clear(None, None)` 调用（写到 V5.A 实装时落地），或留 phase-2

## V5.B — 18 讲全量 audio-only smoke

### 前置

V5.A 合入 + 4 关全绿 + commit。

### 命令

```bash
mkdir tmp/v5_audio_18 2>nul
sjtu canvas-video download 88168 \
    --lectures all --channel 0 --audio-only \
    --to tmp/v5_audio_18 --yaml
```

`--channel 0` 老师机位单路（用户在 brainstorming Q2 选定，理由：教室麦克风同源，audio-only 双路冗余）。

### 后台 / 监控

`run_in_background=true` Bash，每 ~15 / 35 / 55 min 用 `Get-ChildItem tmp/v5_audio_18 *.m4a | Measure-Object` 看产出文件数 + 总 bytes 增长。

### 预期

- 18 m4a，~360-450MB（~20MB/讲，前观察 840MB mp4 → 20MB AAC 比例稳定）
- 单讲耗时 ~80s 下 mp4 + ~21s ffmpeg + 删 mp4 = ~110s
- 18 讲总 ~33min 理论；含 504 反复 + LTI launch 起手 ~20s + 进度 stderr 打印开销，~50-70min 实际
- LTI launch 在 batch 起手发 1 次（V4 已是这样，V5.A 在批量内不影响；V5.A 只让 BATCH 之前 / 之后 的零散命令命中缓存）

### 回收检查清单

- 18 个 `*_ch0.m4a` 全产出
- envelope `succeeded == 18 / failed == 0`（允许 skipped 计入：若中途被打断重跑 skip 路径）
- 总 bytes / 总耗时记录到 `tasks/lessons.md`（V5 章节）
- 抽样 ffprobe 一个 m4a：`ffprobe -v quiet -print_format json -show_streams <file>`，codec_name=aac
- `--audio-only` 默认删 mp4，目录里只看到 m4a（除非传 `--keep-mp4`）
- batch 完成后跑 `sjtu canvas-video list 88168 --yaml` < 1s 确认 V5.A 缓存命中（V5.B 是 V5.A 的端到端验证）

### 风险

- **风险**：单讲 504 触发反复重试拖长时间 → V3 已配 `[0, 3000, 10000, 25000]ms` backoff 救场，单讲最坏 ~38s 入网络层。可接受
- **风险**：磁盘空间 ~500MB → 检查 `tmp/v5_audio_18` 所在分区可用空间 ≥ 1GB

## V5.C — 语音转录项目调研

### 输出

`tasks/canvas_video_transcription_research.md`，~200 行，6 节。

### 范围

- 不写代码，不写集成
- 不调真实模型测 WER（留 V6 决策时做）
- 出"V6 该装哪个项目"的明确推荐 + 集成草图

### 大纲

1. **背景**：Canvas `videSrtUrl` 默认 null（CP-V0 调研证），有也准确度差（用户原话"有出入"）→ 自带语音转录
2. **候选 4 家**
   - **faster-whisper**：OpenAI Whisper large-v3 + CTranslate2 量化，~25× 普通 whisper，中文优秀，SRT/VTT 现成
   - **WhisperX**：Whisper + wav2vec2 强制对齐，词级时间戳，需 GPU
   - **paraformer (FunASR)**：阿里达摩院专精普通话，中文 SOTA，但生态闭、模型走 modelscope
   - **商用云 API**（讯飞 / 火山 / 腾讯）：直接出结果，收费，需联网，企业账号繁
3. **对比维度**：模型大小 / 速度（×real-time）/ 中文 WER（业界公开报告） / 字幕格式 / 部署门槛 / 成本
4. **推荐：faster-whisper + large-v3**
   - 综合最优：免费、本地、中英混说稳、SRT 现成
   - GPU 加速 5-10× real-time；CPU large-v3 也能跑（慢 1-3 min/min audio）
   - paraformer 中文略胜但生态闭、不想引 modelscope 流程
   - 可选回退路径：低端 CPU 上跑 base 或 small 模型，质量降但速度快
5. **V6 集成草图**
   - 命令：`sjtu canvas-video transcribe <m4a> [--model large-v3] [--language zh] [--out <srt>]`
   - 调用方式：`std::process::Command` 调 `whisper-ctranslate2` 子进程（同 V4 ffmpeg 范式，零 Rust deps，不引 Python 运行时）
   - 用户自装：`pipx install faster-whisper-cli` 或 `pip install -U whisper-ctranslate2`
   - CLI 探测：仿 ensure_ffmpeg 写 ensure_whisper，缺工具时给 install hints
   - 输出：SRT 落到与 m4a 同目录、同 stem
   - 批量：`--all` 复用 V4 fail-soft 框架，跑完出 `transcribed_count` + 总耗时 envelope
6. **风险 / 待 V6 验证**
   - 18 讲 large-v3 单 m4a 单机 wall time（V5.B 跑完才能基准）
   - ZH 错词率 / 数学公式 / 专业词汇覆盖
   - phase-2 是否考虑 cloud ASR fallback（成本敏感场景）
7. **不取**
   - Canvas 字幕（`videSrtUrl`）—— 平台已知不准
   - Python 运行时直接嵌入 sjtu-cli —— 引来巨依赖、部署变复杂
   - GPU-only 路径（要照顾 CPU-only 用户）
